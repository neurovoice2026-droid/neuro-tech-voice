# Slice A1: agent conversation behaviour

ASR, turn-taking, TTS, languages, built-in tools and data collection of the
ElevenLabs agent. Every field below was checked against the official OpenAPI
document (`api.elevenlabs.io/openapi.json`, downloaded 2026-10-07), and
`tests/elevenlabs-spec-contract.test.ts` now checks the whole agent body
against the Create Agent schema on every test run.

Vendor behaviour that could only be read from the spec or docs, not tested
live, is marked **unverified live**.

## 2. Endpoints and fields

Read-only catalogue endpoints (new module `lib/elevenlabs/api/models.ts`, platform use only, never proxied to tenants):

- `GET /v1/models` → `ModelResponseModel[]` (`model_id`, `can_do_text_to_speech`, `languages[].language_id`).
- `GET /v1/convai/llm/list` → `LLMListResponseModel.llms[]` (`llm`, `available_reasoning_efforts`, `deprecation_info`).

Agent body (create and PATCH, `buildElevenLabsAgentBody`, new pure module `lib/elevenlabs/conversation-behaviour.ts`):

- `conversation_config.asr.{quality, provider, user_input_audio_format, keywords}`
- `conversation_config.turn.{spelling_patience, interruption_ignore_terms, interruption_ignore_term_languages, merge_with_default_ignore_terms, transcribe_on_disabled_interruptions, soft_timeout_config.*}`
- `conversation_config.tts.{model_id, expressive_mode, text_normalisation_type, stability, similarity_boost, speed}`
- `conversation_config.vad.background_voice_detection`
- `conversation_config.conversation.dtmf_input_settings.{dtmf_input_timeout, hash_terminator, redact_input}`
- `conversation_config.language_presets{lang}.overrides.{agent.{first_message, language, max_conversation_duration_message}, tts.model_id, turn.soft_timeout_config.{message, additional_soft_timeout_messages}}`
- `conversation_config.agent.{disable_first_message_interruptions, max_conversation_duration_message}`
- `conversation_config.agent.prompt.{temperature, ignore_default_personality, enable_reasoning_summary, reasoning_effort}`
- `conversation_config.agent.prompt.built_in_tools.{skip_turn, language_detection, voicemail_detection.description}`
- `conversation_config.agent.dynamic_variables.dynamic_variable_placeholders.ntv_call_direction = 'inbound'`
- `platform_settings.data_collection.outcome.enum`

Client data at call start: `conversation_initiation_client_data.dynamic_variables.ntv_call_direction` (register-call, native outbound-call).

## 3. Migrations

None. New settings live in the existing `agents.conversation_settings` and `agents.voice_settings` JSONB columns (tenant-writable through `PATCH /api/agent`, validated by zod; stored values without the new keys read as the defaults).

## 4. Environment variables

| Name | Default | Meaning |
| --- | --- | --- |
| `ELEVENLABS_TEXT_NORMALISATION` | `elevenlabs` | `tts.text_normalisation_type`: `elevenlabs` (normaliser after generation) or `system_prompt` (LLM writes numbers as words). Any other value → `elevenlabs` (warning in diagnostics). |
| `ELEVENLABS_REASONING_EFFORT` | empty (= `auto`) | Preferred `prompt.reasoning_effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`). Used only when the configured LLM lists it; otherwise the lowest level the LLM supports; nothing when the LLM has no configurable reasoning. |

Existing variables with changed validation: `ELEVENLABS_TTS_MODEL_EN`, `ELEVENLABS_TTS_MODEL_MULTILINGUAL` now accept only `eleven_flash_v2`, `eleven_flash_v2_5`, `eleven_v4_turbo`, `eleven_v3_conversational` (deprecated turbo values still map to flash; anything else falls back to the default and is reported by diagnostics).

## 5. UI changes

- Conversation tab, "Conversation settings": new switches "Ignore short acknowledgements" (disabled when interruptions are off), "Fill pauses while looking things up", "Wait when the caller asks for a moment", "Filter background voices"; voicemail switch renamed "Voicemail detection (outgoing calls)" with corrected copy; temperature copy says what "off" means.
- Conversation tab, "First message": note that the greeting cannot be interrupted, warning above 300 characters.
- Conversation tab: new "Additional languages" card (up to 3, checkboxes with flags, primary excluded) and "Speech recognition" card (keyword chips with add/remove, inline validation, counter).
- Voice tab: new "Voice tuning" card (stability, similarity, speed sliders; per-value "Default" reset; guidance from the ElevenLabs docs).

## 6. Rollout

Every agent's body changes (new keys), so its config hash changes. Existing agents get the new behaviour at their next sync (any save of a provider field, or `POST /api/agent/sync`); a platform-wide push of config changes to every agent belongs to the platform-config rollout work. Until then they keep the old configuration (nothing breaks).

## 7. Manual staging verification (no live calls are automated)

1. Save the Conversation tab once on a staging agent; `GET /v1/convai/agents/{id}` must show the fields of section 2 with the values sent (soft timeout 3 s, ignore terms, `spelling_patience: auto`, `disable_first_message_interruptions: true`, `text_normalisation_type: elevenlabs`, tuning 0.5/0.8/1.0 with "default", `skip_turn` tool).
2. Set stability 0.3, save, then "Default", save: the agent must show 0.5 again (reset reaches the provider).
3. Call the app-routed number: say "Alo?" during the greeting, the greeting must finish; ask something that needs the knowledge base and check that a localized filler plays only after a slow (> 3 s) answer; say "mhm" while the agent talks, it must keep talking; say "o secundă, mă uit în calendar" and stay silent ~15 s: the agent waits, then checks in.
4. Add English as an additional language to a Romanian agent, call and answer in English in your first reply: the agent must switch to English (preset model `eleven_flash_v2`). Check `language_presets` on the remote agent and that the knowledge base still answers (RAG model is now multilingual; documents may need re-indexing, slice E).
5. Remove the additional language, save, `GET` the agent: confirm whether the removed preset disappeared (PATCH merge semantics) and record the result for slice A2.
6. Enable voicemail detection. Inbound call (app-routed and, if available, native number) playing a recorded "leave a message after the tone" greeting: the agent must NOT hang up. Outbound test call to a phone with voicemail: the agent leaves the message or ends the call.
7. During a call, type digits on the keypad (app-routed and native): confirm they reach the agent and the transcript (`dtmf_input_settings`, unverified over register-call).
8. Enable "Filter background voices" and call with a TV in the background; compare false interruptions with it off.
9. `GET /api/admin/voice/diagnostics` with `ELEVENLABS_TTS_MODEL_MULTILINGUAL=eleven_v4_turbo`: no language problem expected for the 14 languages if `/v1/models` lists them; with a typo the variable is reported.
10. Check `reasoning_effort` on the remote agent equals the lowest level `GET /v1/convai/llm/list` reports for the LLM (or is absent), and compare first-response latency before/after.

## 8. Remaining limitations

- `language_presets`, removed `asr.keywords` entries and other map keys rely on the undocumented PATCH merge semantics (see bugs table).
- Previews (`/api/voices/preview`, first-message preview) do not apply the voice tuning yet: the preview endpoint belongs to the voices slice.
- The Cartesia fallback is single-language and receives only `speed` from the tuning.
- Per-language voices for presets are not offered (later).
- DTMF over register-call, `background_voice_detection` quality and the ElevenLabs normaliser on Romanian prices/dates are **unverified live**.
- `client.ts` now exports `req`, `T` and `Ctx` (needed by the new `lib/elevenlabs/api/*` modules; no behaviour change). It still exports the older, minimally typed `listLlms()`; new code uses `lib/elevenlabs/api/models.ts`.
