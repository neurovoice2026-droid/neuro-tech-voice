# Instagram reels: build pipeline (ig1–ig4)

Label `synth`. Written on 2026-10-06 at HEAD `4ea0aa8` (`claude/remotion-trailer`). This is a planning document: no code was changed.

It turns `docs/ig/SCRIPT.md` into four renders without moving a byte of the delivered films:
- film 1 `main` is FROZEN;
- film 2 `kb` is DELIVERED.

It builds on:
- `docs/kb/PIPELINE.md`: the multi-film pipeline these reels extend;
- `docs/ig/RESEARCH-product.md` §2–3: the kit, hazards G1/G2, render path;
- `docs/ig/RESEARCH-reels.md` §2: Instagram specs.

Paths are relative to `trailer/`.

---

## 0. Decisions

1. **Four films, one per reel: `ig1`, `ig2`, `ig3`, `ig4`.** Each has its own timeline, mix, stamp, QA folder and outputs. They share one entry point (`src/ig/index.ts`), one voice set and one sound driver.
2. **`scripts/films.mjs` stays byte-identical.** The brief says "additive only in `scripts/films.mjs`", but that file is an input to film 2's mix hash. `scripts/kb/hash.mjs` reads its bytes (`hash.mjs:44`). Adding even one entry makes `check-mix --film=kb` fail with "mix.wav is stale", and the next kb build rewrites `public/kb/sfx/mix.wav`. That breaks the gate "film 2's sound hash unchanged".
   - **So the additions go in a sibling registry, `scripts/ig/films.mjs`, with the identical field set.**
   - A merged view, `scripts/registry.mjs`, combines the two.
   - The five shared tools switch one import line each to that merged view.
   - This is the research's recommendation (RESEARCH-product §3.2).
3. **IG public files live under `public/ig/`.** `scripts/bundle-digest.mjs` learns that `ig/` is another film's public data (§3.3). Without that, film 1's verify gate 8 fails and film 2's chunk plan reads "picture changed".
4. **Tessa only.** There is one voice role (`ava`) and one combined `scripts/voice-lines-ig.json`, **not split**: all four entries point at it (§4).
5. **Timeline:** 30 fps × SUB 4 = 120 fps, 1080×1920 at `--scale=1`, 120 BPM, film 1's constants re-exported. Picture masters are rendered in act-aligned chunks.
6. **Delivery per reel:**
   - H.264 High at 1080×1920, 120 fps, Level 5.1, ≤ 28 MB, the client's spec;
   - a 60 fps Level 4.2 copy, the file to upload to Instagram;
   - a cover PNG.
7. **Sound:** an IG master at −14 LUFS integrated, ≤ −1 dBTP after AAC.

**Rooms:** `roomAt` returns `'white'` for the pearl reels and `'night'` for ig2. These are the only two rooms `mix.mjs` has.

**`MIX` for Instagram:**

```ts
export const MIX = {
  file: `ig/sfx/${REEL}/mix.wav`,
  lufs: -14,                 // Instagram delivery target (films: -15.5)
  ceiling: -1.5,             // dBTP in the mix; ≤ -1.0 dBTP after AAC is checked on the file (§9)
  fadeOut: [SEAM, END],      // SEAM = END - 14 (after the brand's last sample; else the reel gains a beat)
  fadeK: MIX1.fadeK,         // exponential, < -60 dBFS on the last frame
  impact: { ...MIX1.impact, at: IMPACT },                    // tune rideDb / ceil only if check-mix's lead fails
  name: { ...MIX1.name, voice: 'ig1-07' },
  arc: { ...MIX1.arc, windows: [/* the reel's music-forward window, below */] },
  dialogueLufs: -18.5,       // keeps the films' 4.5 LU voice-under-master balance at the louder master
  dialogueTol: MIX1.dialogueTol,
  dialogueCeil: MIX1.dialogueCeil,   // -2.5: voice transients never drive the master limiter
  cutRoom: MIX1.cutRoom,
  airLp: MIX1.airLp,
```

### 6.2 `scripts/ig/generate-sfx.mjs [--force] [--only=ig2]`
`sfx.mjs` strips `--film=`, so the driver builds every reel by default; each reel is skipped by its own hash. Steps:
1. **Contract check** per reel:
   - every export in §6.1 is present;
   - `VOICES` is sorted;
   - `MIX.name.voice ∈ VOICES`;
   - `MIX.file` / `BED.file` are directly in `ig/sfx/<reel>/`;
   - rooms are only `night` or `white`;
   - every number `master()` reads from `MIX` / `DUCK` / `BED` is finite;
   - every voice WAV exists.
2. **Library:** collect the unique `CUES[].file` values (all `ig/sfx/lib/<name>.wav`).
   - Byte-copy each missing one from its source, film 1's `public/sfx/<name>.wav` or film 2's `public/kb/sfx/<name>.wav`. **Read-only on the source.**
   - Record the source path and its sha256 in `public/ig/sfx/lib.json`.
   - If a source is missing, **stop with a message**. Never run film 1's or film 2's driver from here.
   - Copies are made once, so a future rebuild of a film's library cannot change an IG mix.
3. **Hash and skip:** `igHash(T)` against `public/ig/sfx/<reel>/mix.json` `.hash`. The QA stems must also exist.
4. **Extras:** only if `scripts/ig/sounds.mjs` defines any, written to `public/ig/sfx/fx-*.wav` at −12 dBFS peak. SCRIPT.md needs none.
5. **Bed:** `scripts/ig/bed.mjs` `bed(T)` reads only `inputs(T)`.
   - Normalise to −20 dBFS peak.
   - Write `public/ig/sfx/<reel>/bed.{wav,json}`, cached on `bed.mjs` + `dsp.mjs` + `inputs(T)`.
   - The mix always receives the bed as read back from `bed.wav`.
6. **Master:** `master(T, lib, bedSt, { publicDir: 'public/ig' })` from `scripts/audio/mix.mjs`, **unchanged**. It reads voices from `public/ig/voice/`.
7. **Outputs:** write the stems and `cue-timeline.txt` to `out/audio/ig/<reel>/`, staging temp files in `out/audio/ig/.tmp/` (never inside `public/`). Write `mix.wav`, then the stamp (`hash`, frames, samples, sr, report). Write the stamp only for a finite LUFS and true peak. Remove stale files **only inside `public/ig/sfx/<reel>/`**.

**Never run an IG sound build while a film 1 or film 2 bundle is being made** (H15: `public/` is listed by every bundle).

### 6.3 `scripts/ig/bed.mjs`: four arrangements, film 2's instruments copied
The instrument code is **copied** from `scripts/kb/bed.mjs` (felt piano, pad, strings, kick, shaker, rim, snare roll, pluck, sub, hall, glue, bus limiter). That file exports only `inputs` / `bed`; reading it is fine, but importing its internals is not possible and editing it is forbidden.

All arrangements are 120 BPM in E major, and every one ends with a half-bar snare roll into the impact (E chord, crash choked before the name), then the chord ringing into the fade.

| Reel | Arrangement (moments read from `T`) |
|---|---|
| ig1 | "Shift pulse": shaker 8ths + muted felt-piano ostinato on E from f0 → pad and strings open an octave at the cascade → light kick on 1 and 3 in `does` → thins to piano in `desk` → build |
| ig2 | silence plus room tone until the pickup → muted B–E ostinato with sub on 1 → brushed shaker from the availability check → A → B lift on "booked" → strings under the cascade → thins under the gate → build |
| ig3 | the timer tick is the rhythm (every 30 f) over a low E pedal and B–E dyads → E – C#m7 – A – B from the pickup, ticks doubling → **dead stop of the tick at HANGUP** → high piano line → build |
| ig4 | pluck call-and-response riff with soft kick and rim → chord building on the landings → **hard stop on the sample** at the stop-time (room tone at −60 dBFS air, never digital zero) → warm pad under the fallback → bed returns on "says so" → build |

The cue lists per beat are in SCRIPT.md. Every ring is a key hit at one level (film 2's `RING_DB` rule); non-key hits duck −5 dB under speech through `buildCues`.

### 6.4 `scripts/ig/hash.mjs` `igHash(T, root)` = sha256 over:
- the bytes of `src/ig/<reel>/timing.ts`, `src/ig/common/*.ts`, `src/ig/voice.generated.ts`, `src/lib/cuesheet.ts`, `src/timing.ts`, `src/voice.generated.ts`;
- `scripts/ig/*.mjs` (except the QA-only `render-par`, `finish`, `check-delivery`, `check-zones` and `verify-film2`), `scripts/ig/films.mjs`, and `scripts/audio/{dsp,mix,loudness}.mjs`;
- JSON of `{CUES, VOICES, SCENES, DURATION, BED, MIX, DUCK}`;
- the sha256 of every `public/ig/voice/<id>.wav` in `VOICES`, `public/ig/sfx/lib.json`, and the sha256 of every library file `CUES` references.

It never reads `scripts/films.mjs`, `scripts/registry.mjs`, `scripts/kb/**` or anything of film 2's.

### 6.5 check-mix targets per reel (`check-mix --film=ig<n>`, PASS required)
- **Loudness:** integrated −14 ± 1 LUFS; true peak ≤ −1.0 dBTP (4× oversampled); no clipping.
- **Dialogue:** every line at −18.5 ± 0.5 LUFS in the dialogue stem; every word SII ≥ 0.7; the name (`ig1-07`) SII ≥ 0.9.
- **Climax:** the impact's momentary loudness ≥ the loudest dialogue + 1 LU, and ≥ the 400 ms before it + `suck`.
- **Arc:** the converge tops the reel's window by `arc.lead`.
- **Tail and files:** the end tail < −60 dBFS on the last frame; effect files ≤ −12 dBFS peak, bed ≤ −20 dBFS peak; the stamp hash is current.
- **Delivery file** (after AAC, §9): integrated −14 ± 0.5 LUFS, true peak ≤ −1.0 dBTP.

## 8. Render and encode

### 8.1 The bit budget comes first: probe before building scenes
At ≤ 28 MB for 22–26 s, the 120 fps file gets 8.2–9.7 Mb/s of video. At 1080×1920×120 that is ≈ 0.033–0.039 bits per pixel per frame, so temporal noise is the most expensive thing the encoder sees.
- **`IgFinish` re-seeds the grain and the dark dither once per timeline frame (30 fps), not per render frame.** It passes `frame={Math.floor(t)}` to film 1's `Grain` and `Dither`, which accept a `frame` prop. That cuts the noise's temporal entropy 4×, and at 120 fps it still reads as living texture.
- **`MeshGround`:**
  - `dither` = 1 on ig2's night ground; 0.5 on the pearls, or 0 where a 1-level step cannot be seen;
  - `grain` = 0 (the finish provides it).
- **Probe (gate before any scene work):** render 2 s strips and push them through §8.3 at the reel's real bitrate:
  - ig2 f0–60 (night ground + RingPulse + clock), 240 render frames;
  - ig1 f255–315 (the teal cascade on pearl).

  Inspect for banding rings, plateaus > 8 px and grain smear. Adjust grain strength and dither until clean, **then** build.

### 8.2 Picture master: `scripts/ig/render-par.mjs --film=ig<n> [--workers=3]`
It copies `scripts/kb/render-par.mjs` and changes the following:
- **Settings:** `scale = 1`, intermediate `crf = 12` (HEVC, `NTV_HEVC=1`; `remotion.config.ts` adds `aq-mode=3`), `concurrency = 1` per chunk, and several chunks in parallel. The comp is `film.comp + '9x16'`.
- **Bundle:** if `out/master/bundle-ig` is missing, it builds it itself, after `npm run sfx:ig`:

  ```
  NTV_SKIP_SFX=1 npx remotion bundle src/ig/index.ts --out-dir out/master/bundle-ig
  ```

  `plan.json` records `{bundleSha (bundleDigest drop isSoundStatic), total, chunk, scale: 1, crf: 12, concurrency}`.
- **Act-aligned chunks:** every chunk starts on an act's mount frame (`(from − pre) × 4`), so no glide layer re-rasters mid-act (RESEARCH-product §2.4.4). With `pre = 0`, the ranges in render frames are:

  | Reel | Chunks |
  |---|---|
  | ig1 | 0–419 · 420–1019 · 1020–1439 · 1440–1919 · 1920–2339 · 2340–3119 |
  | ig2 | 0–419 · 420–1859 · 1860–2111 · 2112–2639 |
  | ig3 | 0–959 · 960–1739 · 1740–2183 · 2184–2879 |
  | ig4 | 0–359 · 360–1379 · 1380–2063 · 2064–2375 · 2376–3119 |

- **Per-chunk command:**

  ```
  NTV_SKIP_SFX=1 NTV_HEVC=1 npx remotion render out/master/bundle-ig IG<n>-Reel-9x16 <dir>/<a>-<b>.mp4 \
    --frames=<a>-<b> --scale=1 --concurrency=1 --muted --codec=h265 --crf=12
  ```

  It writes into `out/master/IG<n>-Reel-9x16-x1/` with `.done` markers, so it is resumable.
- **Join:** concat copy into `out/ig/master/<outName>-1080p120-hevc.mp4`, a muted picture master.
- **Throughput:** measure on the §8.1 strips first. The 4K history suggests very roughly 0.5–1.5 s per frame per worker at 1080p, so 11,760 render frames for the four reels take ≈ 0.5–1.5 h on 3 workers.

### 8.3 Delivery: `scripts/ig/finish.mjs --film=ig<n>`
Use Remotion's bundled ffmpeg directly: `node_modules/@remotion/compositor-linux-x64-gnu/ffmpeg`, with `LD_LIBRARY_PATH` set to that folder. Spawn it with an argument array. The `npx` wrapper mangles commas, and this build has no `fps` or `select` filter. There is no system ffmpeg.

**Budget per reel** (decimal 28 MB, 3 % container margin, AAC 192 kb/s): `video_kbps = floor(28e6 × 8 × 0.97 / seconds / 1000) − 192`.

| Reel | Seconds | Video kb/s | maxrate / bufsize |
|---|---|---|---|
| ig1 | 26.0 | **8164** | 12246 / 16328 |
| ig2 | 22.0 | **9684** | 14526 / 19368 |
| ig3 | 24.0 | **8861** | 13291 / 17722 |
| ig4 | 26.0 | **8164** | 12246 / 16328 |

**A. The 120 fps file (client spec):** `out/ig/deliver/<outName>-1080p120.mp4`

```
V="-c:v libx264 -preset slow -profile:v high -level:v 5.1 -pix_fmt yuv420p -b:v ${KBPS}k -maxrate ${MAX}k -bufsize ${BUF}k
   -x264-params aq-mode=3:keyint=240:min-keyint=24
   -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv"
ffmpeg -y -i <hevc master> -map 0:v:0 $V -pass 1 -passlogfile out/ig/.x264-ig<n> -an -f mp4 /dev/null
ffmpeg -y -i <hevc master> -i public/ig/sfx/ig<n>/mix.wav -map 0:v:0 -map 1:a:0 $V -pass 2 -passlogfile out/ig/.x264-ig<n> \
   -af volume=-0.25dB -c:a aac -b:a 192k -ar 48000 -ac 2 -t <DURATION/30> -tag:v avc1 -movflags +faststart <out>
```

- **Level 5.1 is the minimum** at 1080×1920×120: 979,200 MB/s against the 983,040 limit. Level 4.2 tops out near 64 fps. Never copy finish-master's `-level:v 4.2` here.
- `-0.25 dB` is film 2's `DELIVERY_GAIN_DB` (AAC overshoots at the impact). **Copy the constant, don't import `finish-master.mjs`.**
- **Size loop:** if the file is ≥ 28,000,000 bytes, re-encode at −3 % video and repeat.

**B. The 60 fps upload copy (the file to post):** `out/ig/deliver/<outName>-1080p60-ig.mp4`
- Same budget and audio.
- `-vf tinterlace=drop_even` keeps render frames 0, 2, 4, … (exact 2:1, no resampling).
- `-level:v 4.2 -x264-params aq-mode=3:ref=4:keyint=120:min-keyint=12`.
- Instagram's published spec is 23–60 fps, H.264, ≤ 25 Mb/s VBR, AAC 48 kHz (RESEARCH-reels §2.4).

**C. Cover:**

```
NTV_SKIP_SFX=1 npx remotion still out/master/bundle-ig IG<n>-Cover-9x16 out/ig/deliver/<outName>-cover.png --frame=0 --scale=1 --image-format=png
```

Plus the 3:4 crop for QA (`-vf crop=1080:1440:0:240`).

**MP4 edit lists:** the muxer writes an `elst` for AAC priming, so the audio starts on frame 0 (check-render proves lag 0). In-app phone uploads accept it. Only the Graph-API publishing spec forbids edit lists. If the reels are ever published through the API, make an API copy with `-use_editlist 0` and re-check the lock.
